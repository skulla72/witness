# Native connection fallback and iOS push signing preparation

**UNPUBLISHED LOCAL SOURCE — NOT DEVICE, SIGNING OR SUBMISSION APPROVAL**

## Connection-error screen

- Installed Capacitor core/iOS/Android: 8.5.2. Its CLI configuration declares
  `server.errorPath`; iOS navigation-failure handlers and Android main-frame
  network-error handling load that local URL. Configured `errorPath: "index.html"`
  from `mobile/webroot`; no custom proxy, plugin or transport exception added.
- Retry is a normal accessible link to **https://witnessmovement.com**, not
  `location.reload()`. It works without JavaScript or a Capacitor bridge.
  The error page has no remote style, font, image or script dependencies.
  Keyboard focus is visible and the page can scroll on small screens.
- Removed the unsupported saved-writing/automatic-send promise. This page
  cannot establish whether unfinished writing was saved or sent.
- Production destination, app ID, cleartext prohibition and mixed-content
  prohibition are unchanged. A failed retry should enter Capacitor's failure
  handling again; successful retry should load production, not `/index.html`.
  Actual device behavior is still unverified. This hook does not establish
  recovery from every HTTP error, JavaScript failure or server outage.

## iOS push entitlement preparation

- Actual app target now declares the Push Notifications capability and selects
  `App/App.Debug.entitlements` for Debug (`aps-environment: development`) and
  `App/App.Release.entitlements` for Release (`aps-environment: production`).
- Existing bundle ID `com.commonlight.witness`, automatic signing, AppDelegate
  plugin callbacks, Codemagic workflow and reusable signing identities remain
  unchanged. No team, certificate, profile or APNs key was invented.
- These are requested entitlements, **not evidence of signed entitlements**.
  The existing signed workflow requests an App Store archive. Debug device
  signing needs a matching development profile; that distribution workflow
  needs a matching production profile. Xcode/export/profile selection is
  authoritative; do not use a development profile for this Release request.
- No background-push mode, provider credential or delivery functionality was
  added. Native registration, token routing and delivery are unverified.

### Required owner/signing checks before an authorized native build

1. Apple Developer → Certificates, Identifiers & Profiles → Identifiers →
   existing **com.commonlight.witness** App ID: verify Push Notifications is
   enabled for the correct existing team. Do not create a replacement App ID.
2. In that same portal, Profiles: verify the existing development/distribution
   profiles include the push entitlement for the intended environment.
   If stale, authorized profile regeneration/refetch is needed while preserving
   the existing signing certificate/private key. No such operation ran here.
3. Codemagic → Team settings → Team integrations → Developer Portal →
   **Codemagic API Key**: owner must validate the correct active team/key and
   signing permissions. Historical Apple 401 remains unresolved. Workflow-list
   access does not prove this integration works.
4. After separate authorization and a successful signed build, inspect the
   actual app's `codesign -d --entitlements :-` output and embedded profile
   locally for matching bundle/team and `aps-environment`; do not post
   credential/profile bodies. Confirm development vs distribution behavior.
5. Real iPhone/Android: cold-launch offline, verify the bundled page, retry
   while still offline, restore connectivity and retry into production.
   Check keyboard/screen reader/large text. On an authorized iPhone build,
   verify push permission and native registration before separately authorized
   delivery tests with the actual provider/token type. Android Firebase setup
   and existing native-session limitations are not resolved by this change.
